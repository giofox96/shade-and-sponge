**Update 7 Oct (after literature review, see `notes/topic_decision.md`): Florence is now preferred.** Its pluvial flood type is documented, there is an HSG 1:10,000 layer, and there are hotspot maps (Pacetti et al. 2022). Bologna's Oct 2024 extents describe a mixed, culvert-driven event that trees cannot meaningfully affect. Original reading kept below for the record.

**Original reading:** Bologna has the stronger validation case: an observed, mapped, recent urban event plus soil Ksat. Florence has better terrain and rainfall-design inputs. Both share the same trait gap (interception, root architecture). On current evidence, **Bologna looks better for a validated thesis**, but only if the site is chosen where flooding came from **local runoff, not culvert overflow**. That needs checking against the Oct 2024 perimetration.

### 6.3 Open questions this pass created
- **The ND clause.** Florence's only usable pluvial layer is CC BY-NC-ND 4.0. Deriving a raster from `Layer0.png` and publishing it may not be permitted. Check whether the Pacetti et al. (2022) **article** is CC BY (supplementary normally inherits it); if not, ask the authors for written permission.
- **Returns, not classification.** A leaf-on *classified* cloud is still useless if it was thinned to ground + first pulse: the LAI proxy needs returns **inside** the crown. Any request for the Florence 2023 or Bologna 2023 cloud must ask for **points/m², returns recorded per pulse, and whether vegetation returns are retained** *before* asking about licence.
- **Publication rights.** Both realistic Italian clouds are request-only. Ask explicitly whether derived products (CHM, per-tree LAI, figures) may be published in a thesis **and in a public git repository**.
- **The heat half was never checked for Florence** (EPW station, building heights for UTCI context). The dual-hazard premise rests on the runoff half only so far.
